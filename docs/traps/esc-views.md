# 陷阱档案：Esc 栈与视图跳转

> 来源：本项目 Esc/保存视图交互定稿细则（0.4.8~0.4.12，原 HANDOFF 条目于 2026-09-20 体系改造迁入）。改 `src/escape.ts`、`src/views/save-view.ts`、`src/ui.ts` 前必读。

## 1. Esc 交互语义表（0.4.8 定稿，0.4.9 增补来源区分，测试锁定）

| 场景 | 按 Esc |
|---|---|
| 标签建议列表弹出 | 关闭列表回输入框 |
| 弹窗（设置/标签管理/更多标签/确认框） | 关闭当前弹窗；再按 Esc 作用于下一层 |
| 标签管理·重命名输入中 | 只取消重命名，弹窗不动 |
| 保存视图·有未保存修改（内容/类型/标签/备注/标签框已输入文字任一改动） | 弹「未保存的修改」确认框；确认框内再按 Esc = 取消确认留在原地；连按/连点有防抖不会叠弹窗 |
| 保存视图·无修改（编辑，或主面板「＋新增」进入） | 回主面板 |
| 保存视图·无修改（uTools 指令：收藏文本/Markdown/图片/剪贴板 进入的新建） | 退出插件（与「取消」按钮一致） |
| 保存视图·已保存成功 | 直接离开（主面板来源→回主面板；uTools 来源→退出插件），绝不误弹 |
| 主面板·有搜索词 | 清空搜索词 |
| 主面板·无操作 | 退出插件（uTools 原行为） |

- 离开去向由 `SaveInit.from`（"main" / "utools"）决定，编辑模式恒为回主面板。
- 「取消」按钮与 Esc 走同一套 `tryLeave()` 判定（0.4.9 起「取消」有改动时同样弹确认）。

## 2. Esc 必须经 `src/escape.ts` 统一栈
**现象**：散装 `document` keydown 监听会导致 Esc 行为打架，或视图切换后监听器泄漏（上一个视图的 Esc 逻辑仍在生效）、甚至误退出插件。
**真因**：uTools 在窗口级监听 Esc 退出插件，必须由统一栈在 **capture 阶段 `stopPropagation`** 才能拦住。
**禁令**：新开层用 `pushEsc()` 注册、关闭时注销，禁止局部自建 keydown。
实现：集中式处理器栈（pushEsc/resetEsc/initGlobalEscape）；新层打开时注册、关闭时注销，栈顶消费即 stopPropagation。弹窗/确认框（`src/ui.ts` 的 confirmDialog/openModal）的 Escape 也走 escape.ts。

## 3. 未保存判定范围（0.4.8 定稿）
- **内容（含类型切换）/ 标签（含标签框已输入未回车的文字）/ 备注任一变化即判脏**；只打开不改动不弹。
- 基线在首次渲染后用与保存一致的规范化管线取值（详见 CHANGELOG-DETAIL 0.4.8）。

## 4. 离开去向（0.4.9 定稿，勿再改回「新建一律退出插件」）
- 主面板「＋新增」进入（from:"main"）与编辑模式 → 回主面板；
- uTools 功能指令进入的新建（from:"utools"）→ 退出插件；
- 成功保存后同理。

## 5. 成功浮层「继续收藏」
用 `cb.onNewAgain()` 新开空收藏视图，**不要用 location.reload()**——uTools webview reload 后 onPluginEnter 不再触发，会白屏。

## 6. 已知限制（不要当 bug 反复修）
- uTools 侧主动收起插件（点外部/全局热键触发 onPluginOut）无法拦截，未保存提示只覆盖插件内 Esc 与「取消」。
